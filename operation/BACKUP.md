# Backup and Restore

Status: Approved

## 1. 方針

想定規模では複雑なバックアップ基盤を構築しない。

復旧に必要な業務データを、定期または重要変更前に保存する。

## 2. 対象

優先度高:

- M_USER
- M_PRODUCT
- M_SYSTEM_SETTING
- T_PURCHASE
- T_USER_PRODUCT
- T_NOTE_PURCHASE

優先度中:

- T_WARNING

必要に応じて:

- T_LOGIN_LOG
- T_ACCESS_LOG

ログは完全復旧より、問い合わせ・不正利用確認に必要な範囲を優先する。

## 3. タイミング

- 初回本番投入前
- 大規模CSV取込前
- DDL変更前
- 大量データ修正前
- 必要に応じた定期保存

## 4. 形式

- D1エクスポート
- SQL
- CSV

復旧容易性を優先する。

## 5. 保存先

- 非公開
- GitHub公開リポジトリへ保存しない
- ローカル保存時は紛失・漏洩に注意
- 必要なら暗号化する

## 6. 復旧手順

1. 障害範囲確認
2. 現DBを退避
3. 復旧対象日時決定
4. テスト環境へ復元
5. 件数・主要ユーザー確認
6. 本番復元
7. 権限・購入・note移行を重点確認
8. 復旧後バックアップ作成

## 7. 最低確認項目

- M_USER件数
- 商品別有効権限件数
- Stripe購入件数
- note移行件数
- 未対応Warning件数
- 主要ユーザーの権限
